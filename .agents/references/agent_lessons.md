# Agent Lessons — Website Repo

Repo-specific dos & don'ts. Each entry is one rule + why + evidence (code path / doc). Append a dated
entry when a bug, surprise, or repeated correction proves a durable rule (see
`context_maintenance.md`). Newest at top.

## Rules

- **Edit `src/*.html`, never the generated root HTML.** Root `index.html`, `contact.html`, etc. are
  regenerated by `npm run build:html` from `src/` + `components/`; direct edits to root are
  overwritten. *Evidence:* `scripts/inject-components.js`, `README.md`.
- **Don't hand-edit `sitemap.xml`.** It's generated by `npm run build:data` from `data/*.json`.
  *Evidence:* `scripts/build-data.js`.
- **Preserve existing URLs.** `/patents`, `/patents/:slug`, `/team`, `/team/:slug`, `/contact`,
  `/privacy-policy`, `/terms` must keep working (redirects) — losing them regresses SEO. *Evidence:*
  `vercel.json`, `REVAMP-PLAN.md`.
- **Company positioning is canonical in the `docs` repo, not here.** Pull "what TL does" from
  `/Users/ren/repos/docs/company/identity-and-positioning.md`; the strategy docs here translate it.
  The docs repo wins on conflict. *Evidence:* `.agents/README.md`.
- **Publish only docs-supported facts.** A research pass once speculated an "MIT/Berkeley" background
  for Bill that no doc supports — never put unverified credentials/metrics on the site. *Evidence:*
  `data/team_members.json` bio (chemical engineering & chemistry, no school named).
- **The site sells a studio, not a patent lab.** The current copy ("invent and license technologies")
  is the retired story; default new content to the studio narrative. *Evidence:*
  `strategy/product_vision.md`, `docs/company/roadmap.md`.
- **Hire-the-studio is priority 1; owned products are proof, not a sales funnel.** trevillyanlabs.io
  converts visitors into *clients* (Build + Advise). NewsNook is credibility that links out to
  newsnook.ai — don't build a product-sales flow here. Primary CTA is always *Work with us*; *See what
  we ship → NewsNook* is secondary. *Evidence:* `strategy/product_vision.md` (Discoverability,
  Audiences, Success metrics), `strategy/content_plan.md`.
- **Lead with plain client value; avoid internal jargon in copy.** "product-founder," "AI-native,"
  "two-engine," "agentic" are internal shorthand — not client-facing. The one-liner is: *ships custom
  software for clients, operates its own products, and advises founders and early-stage startups on
  product and go-to-market execution.* *Evidence:* `strategy/product_vision.md` (One-line vision).
- **Be found AND represented accurately by AI (SEO/AEO/LLM).** Discoverability is a first-class
  objective: FAQ for AEO, `llms.txt`, JSON-LD, and `robots.txt` that **allows AI crawlers — training
  and answer/search**. *Evidence:* `strategy/product_vision.md` (Discoverability),
  `decisions/ADR-0004-allow-ai-crawlers.md`.
- **Treat secrets per the global brief.** The Mixpanel token is currently committed in
  `js/analytics/analytics-config.js` — a cleanup item, not a pattern to copy. New keys go to env-config
  / Vercel env. *Evidence:* `security_checklist.md`.
- **This is a product repo, not `ren-agent`.** Don't auto-commit/push; use the branch + PR flow
  (`CONTRIBUTING.md`). Production = `main`, integration = `staging`.

## How to add a lesson

One imperative sentence, then *why*, then *evidence* (real path). Keep it short. If the knowledge is a
cross-cutting decision, write an ADR in `decisions/` instead; if it's a term, add it to `glossary.md`.
